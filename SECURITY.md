# Security policy

This repository builds a static website; it has no server code, no runtime dependencies and handles no user data.

## Reporting a vulnerability

Please report security issues privately through GitHub's **Report a vulnerability** button (Security → Advisories) on this repository rather than in a public issue. Include the affected file or URL, the impact and steps to reproduce. We aim to acknowledge reports promptly.

## Scope

In scope: the generator and scripts in this repo, the CI workflow, and the generated pages (for example XSS through content escaping). Out of scope: the BroCODE app itself and third-party hosting.

## Supported versions

Only the `main` branch (what is deployed to https://codingagent.in) receives fixes.

## Hardening in place

- Strict Content-Security-Policy: `default-src 'none'`, inline scripts allowed only by SHA-256 hash (generated at build time and checked by `npm run verify`), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`. `style-src` still allows inline styles because pages inline their CSS and use per-character animation offsets.
- HSTS (2 years, includeSubDomains, preload), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, a deny-all `Permissions-Policy`, COOP and CORP `same-origin`, `X-Frame-Options: DENY`. See `dist/_headers` (Netlify) and `vercel.json` (Vercel), both generated by `build.mjs`.
- CI runs with `contents: read`, actions pinned to commit SHAs, `persist-credentials: false`, `npm audit`, CodeQL, OpenSSF Scorecard and Dependabot for npm and GitHub Actions.
- A machine-readable contact is published at `/.well-known/security.txt`.
